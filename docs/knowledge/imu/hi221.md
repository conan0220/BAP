# HI221 IMU

## Format Scope

New-generation HI221 nodes and an HI221 Dongle can use the compact `0x63` GWSOL UART payload when the nodes use the `09` RF transmit format.

The `0x62` GWSOL format is a legacy compatibility format. This document focuses on `0x63`; consult the vendor datasheet for complete `0x62` details.

## Required Device Configuration

- HI221 Dongle UART output: `AT+SETPTL=63`
- HI221 node RF transmit format: `AT+TXFMT=09`
- Restart the affected device with `AT+RST` after changing either format.
- Configure the wireless output rate on the Dongle with `AT+ODR`; a node's own ODR does not control Dongle output.
- Use a sufficiently high UART baud rate for the selected output rate. The vendor recommends 460800 or 921600 baud for high frame rates and 921600 baud for 400 Hz in `0x63` mode.

## Coordinate and Orientation Conventions

- Body frame: right-handed North-West-Up (NWU), with the Z axis pointing up.
- Euler rotation order: intrinsic ZYX.
- Euler output order: Roll (X), Pitch (Y), Yaw (Z).
- Euler angle ranges:
  - Roll: -180 to 180 degrees
  - Pitch: -90 to 90 degrees
  - Yaw: -180 to 180 degrees

## `0x63` Payload Layout

The `0x63` payload is emitted by the HI221 Dongle and has a total length of:

```text
8 + 34 * N bytes
```

`N` is the number of nodes in the frame, from 0 through 16. Node blocks are ordered by ascending device ID.

### Gateway header: 8 bytes

| Offset | Size | Type | Description |
|---:|---:|---|---|
| 0 | 1 | `uint8` | Payload tag, always `0x63` |
| 1 | 1 | `uint8` | Gateway network ID (`GWID`) |
| 2 | 1 | `uint8` | Number of nodes in this frame (`N`) |
| 3 | 1 | `uint8` | Reserved |
| 4 | 4 | `uint32` | Gateway timestamp in milliseconds |

### Node block: 34 bytes

Each node block starts at payload offset `8 + 34 * i`, where `i` is the zero-based node index.

| Block offset | Size | Type | Decode as | Description |
|---:|---:|---|---|---|
| 0 | 1 | `uint8` | - | Node block tag, always `0x93` |
| 1 | 1 | `uint8` | - | Node device ID |
| 2 | 6 | `int16[3]` | divide by 1000 | X, Y, Z acceleration in g |
| 8 | 6 | `int16[3]` | divide by 10 | X, Y, Z magnetic field in uT |
| 14 | 6 | `int16[3]` | divide by 10 | X, Y, Z angular velocity in deg/s |
| 20 | 8 | `int16[4]` | divide by 32767 | Quaternion W, X, Y, Z |
| 28 | 6 | `int16[3]` | divide by 100 | Euler Roll, Pitch, Yaw in degrees |

Multibyte numeric values use little-endian byte order.

## Deployment Constraints

- Node IDs under one Dongle must be unique and assigned consecutively from 0.
- Every node ID must be lower than the Dongle's current maximum node count.
- All nodes connected to the same Dongle must use the same RF transmit format.
- The Dongle determines its maximum node count from the configured output rate. According to the datasheet, typical limits are:
  - 400 Hz: 2 nodes
  - 200 Hz: 7 nodes
  - 100 Hz: 16 nodes
